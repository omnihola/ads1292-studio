# P11 Phase 8: XLSX Writer

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`).

**Goal:** Port `xlsx_io.py` — a 2-tab (Events + Data) XLSX writer — to C++ so the GUI/library can produce the same spreadsheet export the Python app does. The only missing C++ io writer.

**Architecture:** An XLSX is a ZIP of XML parts. We add a minimal dependency-free ZIP-**store** writer (CRC32 + local/central/EOCD headers — no zlib; XLSX readers accept stored entries), then build the OOXML parts (5 static + Events sheet + Data sheet) matching `xlsx_io.py`'s XML, then `write_recording_xlsx(csv_path, events, sample_rate_hz)`. **Parity is the SHEET CONTENT** (Events/Data rows + the static parts), not the ZIP bytes — consistent with the project's semantic-parity decisions (HDF5, bundle). Finally wire it into the finalize flow + a "Save XLSX" checkbox.

**Tech Stack:** C++17, CMake, Catch2. `/usr/bin/unzip` for the tests. Oracle: `src/ads1292_studio/xlsx_io.py` (full).

Locate the exact event_id / event_sample_indices signatures via grep/codegraph.
- **XLSX XML (from xlsx_io.py — match exactly):**
  - `_worksheet_xml(rows)`: `<?xml version="1.0" encoding="UTF-8" standalone="yes"?>\n<worksheet xmlns="...spreadsheetml/2006/main">\n<sheetData>\n` + per row (1-based) `<row r="N">` + per cell `_cell_xml` + `</row>\n` + `</sheetData>\n</worksheet>\n`.
  - `_cell_xml(r,c,value)`: ref = `_column_name(c) + r`; if `_is_number(text)` → `<c r="REF"><v>{escape(text)}</v></c>` else `<c r="REF" t="inlineStr"><is><t>{escape(xml_safe(text))}</t></is></c>`.
  - `_is_number`: regex `^-?(0|[1-9]\d*)(\.\d+)?([eE][+-]?\d+)?$` (no leading-zero ints, no '+', no inf/nan).
  - `_column_name(i)`: 1→A … 26→Z, 27→AA (base-26 bijective).
  - `_xml_safe(text)`: drop C0 controls except `\t \n \r`.
  - `escape`: XML escape `& < >` (xml.sax.saxutils.escape — `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`; NOT quotes by default).
  - **Events sheet** (`_events_sheet_xml`): row 1 = the EVENTS_CSV_HEADER (read it from xlsx_io.py / events.py — the column names: event_id, timestamp_seconds, end_seconds, duration_seconds, start_sample_index, end_sample_index, duration_samples, kind, label, notes — CONFIRM the exact header); then per normalized event: `[event_id, f"{ts:.6f}", f"{end:.6f}", f"{dur:.6f}", start_sample_index, end_sample_index, duration_samples, "interval" if dur>0 else "point", label, notes]`.
  - **Data sheet** (`_data_sheet_xml`): the LITERAL CSV rows — Python does `csv.reader(csv_path)` → each row is the split-on-comma fields. The C++ should read the recording CSV file's raw lines, split each on ',' (simple split is fine for this CSV — no embedded commas/quotes in the numeric recording CSV), and emit each as a worksheet row. (Match Python: the Data sheet == the CSV content as cells.)
  - **5 static parts** (`_write_static_parts`): `[Content_Types].xml`, `_rels/.rels`, `xl/workbook.xml` (sheets Events/Data), `xl/_rels/workbook.xml.rels` (rId1→sheet1, rId2→sheet2), `xl/styles.xml`. Copy the exact XML strings from xlsx_io.py.
  - **Layout**: `xl/worksheets/sheet1.xml` = Events, `xl/worksheets/sheet2.xml` = Data. `recording_xlsx_path(csv) = csv with .xlsx`.

### Task 1: minimal ZIP-store writer

**Files:** Create `io/include/ads1292/io/ZipStoreWriter.h` + `io/src/ZipStoreWriter.cpp`; io CMake; Create `tests/cpp/test_zip_store.cpp`; tests CMake.

**Interfaces (namespace `ads1292::io`):**
- `class ZipStoreWriter { public: void add(const std::string& name, const std::string& data); std::string bytes() const; void write(const std::string& path) const; };` — accumulates entries; `bytes()`/`write()` emit a valid ZIP using the STORE method (compression 0).
- Implement: per entry a local file header (sig 0x04034b50, version 20, flags 0, method 0 (store), dos time/date 0, crc32, comp_size==uncomp_size==data.size(), name len, extra 0) + the name + the raw data. After all entries, the central directory (one record per entry, sig 0x02014b50) + the end-of-central-directory record (sig 0x06054b50). CRC-32 (standard polynomial 0xEDB88320) over each entry's data. All multi-byte fields little-endian. (A standard minimal store-ZIP — ~120 lines. No zlib.)

(Or use `unzip -l` + check both names present.) The point: a real `unzip` reads our zip + extracts the exact bytes.
