# P11 (Part-4 Phase 1): Persist CSV + Bundle + H5 on Stop

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`).

**Goal:** Make the C++ live GUI actually persist an acquired recording. Today `worker_.start(dev, mode, "")` passes an empty csv_path → nothing hits disk. After this phase: pressing Stop writes `<recording>.csv` + `<recording>.json` (recording bundle) + optional `<recording>.h5` to `~/Documents/ECG/live/`, finalized on a background thread. Metadata/events use defaults for now (later phases add the input panels + event wiring). This is Part-4 Phase 1 of the GUI-parity build-out (gap roadmap 2026-06-26).

**Architecture:** A testable, Qt-free `finalize_live_recording(...)` io function does the disk work (read the just-written CSV → build provenance → write bundle [+ H5]); the GUI generates a timestamped csv_path at Start, passes it to the worker, and on the worker's `finished(int)` signal spawns a background thread that calls `finalize_live_recording`, then posts a log line back to the GUI thread. The engine already writes the CSV when csv_path is non-empty (AcquisitionEngine::run_live), so persistence is unlocked by supplying a real path + finalizing.

**Tech Stack:** C++17, CMake, Catch2, Qt (gui wiring only). Oracle: `src/ads1292_studio/ui_qt/controller.py` (`_finalize_recording`), `recording_bundle.py`, `acquisition.py`.

### Task 1: `finalize_live_recording` (testable io function)

**Files:** Create `io/include/ads1292/io/LiveRecordingFinalize.h` + `io/src/LiveRecordingFinalize.cpp`; add to io CMake; Create `tests/cpp/test_live_finalize.cpp`; tests CMake.

**Interfaces (namespace `ads1292::io`):**
```cpp
struct FinalizeOptions {
  ads1292::SessionMetadata metadata;                  // defaults for Phase 1
  std::vector<ads1292::EventMarker> events;           // {} for Phase 1
  ads1292::Calibration calibration;                   // Calibration{}
  ads1292::TestProtocol protocol;                     // protocol_template()
  ads1292::dsp::QualityGate quality_gate;             // quality_gate_template()
  std::string acquisition_mode = "live_stream";
  std::string port = "";
  std::string started_at = "";                        // ISO string (or "")
  double sample_rate_hz = 500.0;
  bool write_h5 = true;
  std::string created_at = "";
};
struct FinalizeResult { bool wrote = false; int sample_count = 0; std::string csv_path, bundle_path, h5_path; };
FinalizeResult finalize_live_recording(const std::string& csv_path, const FinalizeOptions& opt);
```
- Logic (mirror `_finalize_recording`):
  - `auto rec = read_recording_csv(csv_path);` (the engine already wrote it). If `rec.samples.empty()` → return `{wrote=false, sample_count=0, csv_path}` (skip degenerate output).
  - Build an `AcquisitionProvenance a; a.csv_name = basename(csv_path); a.acquisition_mode = opt.acquisition_mode; a.port = opt.port; a.started_at = opt.started_at; a.sample_rate_hz = opt.sample_rate_hz;` then `a = a.normalized();` (a SIMPLIFIED provenance — the elaborate finalize_acquisition_provenance with measured-rate attrs isn't ported; document it; it still writes a valid acquisition section).
  - `auto processing = build_processing_settings(/* sample_rate_hz */ opt.sample_rate_hz);` (confirm the arg).
  - `auto bundle_path = write_recording_bundle(csv_path, opt.metadata, opt.events, opt.calibration, a, opt.protocol, opt.quality_gate, processing, opt.sample_rate_hz, opt.created_at);` (returns the .json path).
  - if `opt.write_h5`: build the bundle json (or reuse `build_recording_bundle(...)` returning the json) + `auto h5_path = <csv with .h5>; write_recording_h5(h5_path, rec.samples, bundle_json, attrs);` per the committed H5 signature (READ H5Io.h — match it exactly; if it needs attrs, pass effective_sample_rate etc. or an empty/default attrs object).
  - return `{wrote=true, sample_count, csv_path, bundle_path, h5_path}`.
