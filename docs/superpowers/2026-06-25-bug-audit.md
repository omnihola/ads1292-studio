## A. HEADLINE — recording_bundle feature gap (CRITICAL, partly a SCOPE gap)

The approved spec (`2026-06-24-cpp-qt-full-port-design.md` line 99) made P2 require **bundle 往返** — full read/write of the combined recording bundle (`ads1292-recording-bundle-v1`: metadata+events+calibration+acquisition+protocol+quality_gate+processing in the recording's `.json`). In the Python app this bundle IS the recording's `.json` sidecar; the GUI writes CSV + **bundle** + XLSX on finalize, and the session index reads metadata/sidecars FROM the bundle. Status in C++:

1. **`io/src/Bundle.cpp` is buggy AND never called.** `Bundle.h` redefines local stub `ProtocolStep` (only `name`/`description` — real model has start_seconds/duration_seconds/label/instruction) and stub `AcquisitionProvenance` (7 vs the canonical 12 fields → ODR clash with AcquisitionIo.h). `build_recording_bundle` would emit empty/wrong protocol+acquisition; and nothing in gui/cli/core ever calls it. **[Critical]**
2. **Bundle READ is not wired into the consumers.** `SessionIndexScan.cpp::_metadata_for`/`_sidecar_status` + `BatchScan.cpp` read the `.json` as a plain metadata sidecar (`read_metadata_json`), with no `is_recording_bundle_path`/`metadata_from_bundle` detection. A Python-produced recording (whose `.json` is a bundle) → C++ index/batch reports all-default metadata + flags all 7 sidecars "missing" → wrong package_ready/next_action/repair-plan. **[Critical for interop]**
3. **GUI live-save writes CSV only.** `run_live` persists just the CSV; no bundle/XLSX/H5 (Python controller writes CSV + bundle + XLSX, optional H5). The C++ GUI has no save-recording UI path beyond the CSV the engine writes. **[Important —功能缺失 vs Python finalize]**

→ This is a phase of work (port `recording_bundle.py` read+write, wire it into the GUI finalize + the index/batch consumers, fix Bundle.cpp's stub types), not a one-line fix.
