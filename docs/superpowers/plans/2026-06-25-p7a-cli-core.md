# P7a: Numeric CLI Core (quality_gate + qc / report / verify) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the numeric command-line core — a Qt-free `ads1292_cli` binary with `qc` (quality-gate pass/fail on a recording), `report` (textual quality/HR/PQRST summary), and `verify` (HDF5 integrity check) subcommands — by porting `quality_gate` and reusing the verified P5 DSP + P2 readers.

**Architecture:** A new portable `core/dsp/QualityGate` (pure C++17) implements the quality-gate thresholds + evaluation. A new Qt-free `cli/` library exposes `run_qc`/`run_report`/`run_verify` (each takes a `std::ostream&` + args, returns an exit code) so they are unit-testable without spawning a process; a thin `main.cpp` dispatches subcommands. The CLI links `ads1292_core` + `ads1292_io` only (no Qt — the numeric CLI has no GUI). This is the smallest, highest-parity slice of the Python CLI; the JSON-sidecar ecosystem, PNG/HTML report rendering, and device subcommands are deferred to P7b/P7c/P7d.

**Tech Stack:** C++17, CMake, Catch2. Reuses P5c `compute_quality_metrics`/`quality_label`, P5b `pqrst_review`, P2 `read_recording_csv`/`write_recording_csv`/`verify_recording_h5`/`write_recording_h5`. Oracle: `quality_gate.py`, `cli.py` (`cmd_qc`, `cmd_report`, `cmd_verify_recording`).

## Global Constraints

- **C++17**; `core/dsp/QualityGate` is pure portable C++ (stdlib only, all `double`, no Qt/OS). The `cli/` library + binary are Qt-free (link `ads1292_core` + `ads1292_io` only).
- **Layering**: `QualityGate` depends on `QualityMetrics` (P5c) only. `cli/` depends on `core` + `io`.
- **Branch**: work on `c++`; do NOT touch `main`. `build/` is gitignored.
- **Build/test**: `CMAKE_PREFIX_PATH="/opt/homebrew/opt/qt;/opt/homebrew/opt/hdf5" cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug && cmake --build build -j && ctest --test-dir build --output-on-failure`. (The CLI tests need no Qt platform; HDF5 verify needs the brew hdf5 already on CMAKE_PREFIX_PATH.)
- **Parity gates:** `evaluate_quality_gate` failure strings + pass/fail must match `quality_gate.py` EXACTLY (the failure-message formats are the parity surface). The qc/report subcommand output lines must match the Python `cmd_qc`/`cmd_report` key=value lines and exit codes.
- **`QualityGate` (quality_gate.py):** `double min_duration_seconds=8.0, min_contact_ok_percent=95.0; int min_r_peaks=5; double min_hr_bpm=35.0, max_hr_bpm=180.0; bool require_qrs_clear=true; std::optional<double> max_baseline_drift_counts, max_noise_rms_counts, max_peak_to_peak_counts (all unset)`. `normalized()`: clamp `min_duration_seconds=max(0,·)`, `min_contact_ok_percent=clamp(·,0,100)`, `min_r_peaks=max(0,·)`, `min_hr_bpm=max(0,·)`, `max_hr_bpm=max(0,·)`, the three optionals → `max(0,·)` if set else unset.
- **`evaluate_quality_gate(metrics, gate)` (quality_gate.py, EXACT failure strings):** `gate = (gate or default).normalized()`; `failures=[]`. First, finiteness — for each of `("duration", duration_seconds)`, `("contact %", contact_ok_percent)`, `("median HR", hr_median_bpm)`, `("baseline drift", baseline_drift_counts)`, `("noise RMS", noise_rms_counts)`, `("peak-to-peak", peak_to_peak_counts)`: if `!isfinite(value)` → push `"<name> is not finite (<value>)"`. Then:
  - `duration_seconds < min_duration_seconds` → `"duration {duration:.2f}s < {min:.2f}s"`
  - `contact_ok_percent < min_contact_ok_percent` → `"contact {contact:.2f}% < {min:.2f}%"`
  - `require_qrs_clear && !qrs_clear` → `"QRS not clear"`
  - `r_peaks < min_r_peaks` → `"R peaks {r_peaks} < {min}"`
  - `hr_median_bpm > 0 && hr_median_bpm < min_hr_bpm` → `"median HR {hr:.1f} bpm < {min:.1f} bpm"`
  - `hr_median_bpm > max_hr_bpm` → `"median HR {hr:.1f} bpm > {max:.1f} bpm"`
  - `max_baseline_drift_counts set && baseline_drift_counts > it` → `"baseline drift {v:.1f} counts > {lim:.1f} counts"`
  - `max_noise_rms_counts set && noise_rms_counts > it` → `"noise RMS {v:.1f} counts > {lim:.1f} counts"`
  - `max_peak_to_peak_counts set && peak_to_peak_counts > it` → `"peak-to-peak {v:.1f} counts > {lim:.1f} counts"`
  `passed = failures.empty()`. (`:.2f`/`:.1f` = fixed-precision; replicate with `snprintf`/`std::fixed`.)
- **`QualityGateResult`:** `bool passed; std::vector<std::string> failures; std::string label() const { return passed ? "Pass" : "Fail"; }`.
- **`cmd_qc` output (cli.py, the P7a `qc` subcommand, NO protocol-segment part — that needs the un-ported protocol module, defer):** read CSV → `compute_quality_metrics(samples, sr, source)` → `evaluate_quality_gate(metrics, gate)`; print (in order): `quality_gate=<label>`, `ecg_source=<ecg_source>`, `quality=<quality_label>`, `baseline_drift_counts=<v:.1f>`, `noise_rms_counts=<v:.1f>`, `peak_to_peak_counts=<v:.1f>`, then one `failure=<msg>` per failure. Exit `0` if passed else `2`.
- **`cmd_report` output (the P7a `report` subcommand, TEXT summary — NO HTML/PNG, those are P7c):** read CSV → `compute_quality_metrics` → print the metric fields as key=value lines + `quality=<quality_label>` (a fuller textual summary; the exact lines are defined in Task 3). Exit `0`.
- **`verify` subcommand:** `verify_recording_h5(path)` (P2c) → print `ok=<true/false>` + any failure detail; exit `0` if ok else `2`. (The Python `cmd_verify_recording` verifies a package MANIFEST; the C++ P7a `verify` instead checks a single HDF5 recording's internal integrity hash — the manifest ecosystem is deferred to packaging. Document this mapping.)

std::string write_clean(const std::string& name) {
